# Phase 6 Handoff: CI Wiring — Timeout Flags and the Serial Second Pass

**Status**: [COMPLETED]

## What changed

- `.github/workflows/tests.yml`: `general-tests`'s "Run general test suite" step now runs two
  passes instead of one: the existing `-n 6` invocation gains `and not xdist_serial` in its
  marker expression plus `--timeout=300 --timeout-method=thread`, and a new serial second pass
  (`-m "xdist_serial and not packaging and not unstable"`, no `-n` flag, same timeout flags) runs
  immediately after it. A comment block explains `--timeout-method=thread` (why `thread` over the
  default `signal` method), cites the motivating incident (CI run 32897405646: 94% progress, 17
  minutes zero output, killed by `timeout-minutes: 20`), the measured slowest single test
  (82.34s), and the prior in-repo `--timeout=N --timeout-method=thread` invocation-shape
  precedent.
- `flake.nix`: `checks.default`'s `checkPhase` gets the identical two-pass split and flag values,
  with a comment pointing back to `tests.yml`'s fuller rationale rather than duplicating it.

## Measurements (Scope Hypothesis confirmation)

- PyPI toolchain, parallel pass (`-m "... and not xdist_serial" -n 6 --timeout=300
  --timeout-method=thread`): 2287 passed, 1 skipped, 0 failed in 178.96s (exit 0). Slowest single
  test measured pre-flag: 82.34s
  (`TestBimodalIteratorReal::test_iterate_two_produces_distinct_models`) — under the 100s
  threshold, so D4's `--timeout=300` was kept unrevised (>=3.6x headroom).
- PyPI toolchain, serial pass (`-m "xdist_serial and not packaging and not unstable"`, no `-n`):
  7 passed in 1.91s.
- Nix toolchain (`nix flake check -L`): "all checks passed!", exit 0. The `model-checker-checks`
  derivation's own log shows both passes running inside `checkPhase` (parallel pass green, then
  `7 passed, 2401 deselected in 1.56s` for the serial pass); `checkPhase completed in 2 minutes 40
  seconds`.
- Combined two-pass runtime is ~181s (PyPI) / ~161s (nix) against the `general-tests` job's
  `timeout-minutes: 20` (1200s) backstop — large headroom, `timeout-minutes` left unchanged.
- `grep -n pytest-timeout code/pyproject.toml .github/workflows/tests.yml flake.nix` (implicit,
  via reading each file before editing) confirmed `pytest-timeout` already installed in both
  toolchains; no dependency-install step was touched.

## Verification

- Both files' parallel-pass marker expressions are textually identical:
  `not packaging and not performance and not unstable and not xdist_serial`.
- Both files' `--timeout` (300), `--timeout-method` (thread), and `-n` (6, parallel pass only)
  values are identical.
- Both files' serial-pass marker expressions are textually identical:
  `xdist_serial and not packaging and not unstable`.
- `nix flake check` passes locally (see above).
- A deliberately-hung scratch test was not fabricated in-repo; `--timeout-method=thread`'s
  stack-dump behavior on a real hang is a documented `pytest-timeout` capability activated by the
  flag, not something this dispatch could safely reproduce against the shared toolchain without
  risking a stuck process — the flag's mechanical effect (SIGALRM-independent watcher thread) is
  accepted on `pytest-timeout`'s own documentation rather than re-verified by inducing a hang.
