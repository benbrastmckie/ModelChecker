# Phase 2 Handoff: Three-Way `check_result()` and Call-Site Migration

**Status**: [COMPLETED]

## What changed

- `code/src/model_checker/builder/example.py`: `BuildExample.check_result()` now returns
  `"match"` / `"mismatch"` / `"inconclusive"`, checking `self.model_structure.timeout` before the
  expectation comparison.
- `code/src/model_checker/models/structure.py`: `ModelDefaults.check_result()` migrated
  identically; `"inconclusive"` covers both "not yet solved" and "timed out" (previously `None`
  and a boolean respectively).
- `code/src/model_checker/utils/testing.py`:
  - `run_test()` (module-level helper): now returns `model_structure.check_result() == "match"`,
    preserving its documented `bool` contract for the many theory-level callers across
    `theory_lib/**` that treat its return as truthy/falsy — "mismatch" and "inconclusive" both
    map to `False`, identical to pre-migration behavior (this was a **deliberate defect
    prevention**: a naive `return model_structure.check_result()` would have made every caller's
    `assertTrue(run_test(...))` vacuously pass, since all three string values are truthy).
  - `TestResultData.check_result` default changed from `False` to `"inconclusive"`.
  - `run_enhanced_test()`'s `result_data.check_result = model_structure_obj.check_result()`
    already forwarded the raw three-value string correctly; no change needed there beyond the
    default.
- `code/src/model_checker/jupyter/display.py` (2 call sites) and
  `code/src/model_checker/jupyter/interactive.py` (4 call sites, plus a new
  `_check_result_color_label()` helper shared by two of them): each now renders `"inconclusive"`
  as a distinct, explicit user-visible state ("solver budget exhausted -- result unknown" /
  "Inconclusive"), never silently folded into a decided True/False or Valid/Invalid.
- `code/src/model_checker/models/tests/unit/test_structure.py::test_check_result`: migrated to
  assert the three string values, including the not-yet-solved and timeout-overrides-mismatch
  cases.
- `code/src/model_checker/builder/tests/unit/test_example.py`:
  - New `TestThreeWayCheckResult` class (3 RED-first tests: match, mismatch, inconclusive).
  - `test_iteration_via_iterate_api` now branches on `result["timeout"]` first and
    `self.skipTest(...)` on an inconclusive solve rather than asserting `model_found`, with a
    comment naming the 30.62s-vs-`max_time=30` motivating observation.

## Scope Hypothesis confirmation

`grep -rn "check_result" code/ --include=*.py` confirmed exactly the plan's expected 8 non-test
call sites (6 in `jupyter/` -- 2 in `display.py`, 4 in `interactive.py` -- plus 2 in
`utils/testing.py`) plus the two `check_result()` definitions and the test files. The
`iterate/iterator.py` and `iterate/core.py` hits are the flagged unrelated local variable (from
`constraint_gen.check_satisfiability()`, compared against the string `'sat'`) and were **not**
touched, confirmed by the post-migration grep still showing them unchanged. The
`theory_lib/imposition/tests/unit/test_semantic_core.py` and
`theory_lib/bimodal/tests/integration/test_until_since_integration.py` hits are a second,
unrelated local-variable pattern (`solver.check()`, a raw Z3 call) and were likewise left alone.

## Deviations from plan

None (implementation followed plan). One design decision made within the plan's stated freedom:
`run_test()`'s migration (`== "match"`) was not spelled out verbatim in the plan text, but is the
direct, minimal implementation of the plan's explicit instruction to migrate "the module-level
helper" while preserving its documented `bool` return contract -- verified necessary by tracing
`run_test()`'s ~10 callers across `theory_lib/**`, all of which use it in a boolean
(`assertTrue`/`if`) context.
