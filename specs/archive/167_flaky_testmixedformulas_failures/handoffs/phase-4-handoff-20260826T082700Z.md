# Phase 4 Handoff: Route A -- Plumb max_rlimit through the oracle provider

**Status**: COMPLETED

## What was built

- `oracle/bimodal_logic/errors.py`: `OracleTimeoutError.__init__` gains an optional
  `max_rlimit: int | None = None` parameter. When truthy, `self.context["max_rlimit"]` is set and
  the message names both budgets ("... within {timeout_ms} ms or {max_rlimit} rlimit units...").
  When absent (the default), the message text is byte-identical to before.
- `oracle/bimodal_logic/provider.py`: `find_countermodel()` gains an optional
  `max_rlimit: int | None = None` parameter, inserted into the settings dict only when truthy
  (mirroring `ModelDefaults.solve()`'s own `if max_rlimit:` guard), and passed through to the
  `OracleTimeoutError` raise site. Docstring documents it as the load-independent complement to
  `timeout_ms`, cross-referencing `TESTING_GUIDE.md` section 8.6.
- `oracle/bimodal_logic/tests/test_oracle_interface.py`: new `TestMaxRlimitParameter` class (5
  tests, all atemporal/fast/unmarked) -- default-omits the settings key; a truthy value reaches
  the settings dict; a tiny value raises `OracleTimeoutError`; the raised error's `context` and
  message both name `max_rlimit`; the no-`max_rlimit` message is asserted byte-identical to the
  pre-existing text.

## Scope Hypothesis outcome

Confirmed exactly as hypothesized: `OracleTimeoutError(` has exactly two construction sites
outside `provider.py`, both in `test_cross_oracle_differential.py` (`_StubOracle.find_countermodel`
and a `ref_fn` raise in a differential-report boundary test), and both were unaffected -- the new
parameter is optional and neither site passes it. No additional sites found.
