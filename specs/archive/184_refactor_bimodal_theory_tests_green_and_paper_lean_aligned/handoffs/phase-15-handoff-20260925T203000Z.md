## Key Decisions Made

- **Did not attempt to fix `iterate/constraints.py`'s `is_world`-gating.** This is shared
  framework code all four theories depend on; a change there needs its own regression pass
  across logos/exclusion/imposition, which this bimodal-scoped phase did not have budget for.
  Recorded as a reasoned exclusion with a clear next step (a dedicated extension-point task),
  not silently left for someone to rediscover from scratch.
- **`_calculate_differences` compares each structure's own extracted `certificate`, not a raw Z3
  model.** Both structures have already independently re-checked their own certificate via
  Phase 12's S3 hook by the time iteration ever sees them, so comparing the (already-verified)
  `WitnessFamily` objects directly is both simpler and strictly more trustworthy than re-deriving
  differences from raw Z3 model evaluations the way the retired encoding did.
- **Test verification style: "the blocking clause evaluates to `False` against its own
  reference model," not "two distinct solves produce different models."** Testing the latter
  would require driving the live iteration loop, which (per the discovered gap above) does not
  currently exercise these methods at all -- testing the constraint-construction logic directly
  against a model it was built from is the correct, checkable unit-level claim: a well-formed
  blocking clause must be false when evaluated against the exact model it excludes.

## What NOT to Try

- Do not assume `iterate: 3` on a bimodal example currently produces three genuinely distinct,
  pairwise non-isomorphic certificates through the real `dev_cli.py`/`BuildModule` path -- the
  discovered gap above means nothing currently forces that. Verify empirically before relying on
  it in a later phase's own test.
- Do not "fix" this by giving `BimodalSemantics` a fake `is_world` method just to satisfy
  `ConstraintGenerator`'s `hasattr` check -- that is exactly the kind of compatibility shim the
  project's clean-break philosophy rules out, and it would silently paper over a gap that needs
  an honest fix (an extension point in the shared iterator, not a fake predicate on this one
  theory).
- Do not spend a follow-on phase's budget on rotation/permutation-invariant rejection before the
  live-loop gap is closed -- there would be nothing to actually exercise it with yet.
