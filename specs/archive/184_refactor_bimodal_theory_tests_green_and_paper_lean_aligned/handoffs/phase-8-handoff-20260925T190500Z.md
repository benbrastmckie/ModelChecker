## Key Decisions Made

- **The Phase-7 "one representative position per slot" argument does not extend to fulfilment.**
  Local coherence's biconditional only ever references a position's immediate neighbour (`t+1` or
  `t-1`), so `bit`'s slot-sharing makes asserting it once per slot definitionally equivalent to
  asserting it at every integer position. Fulfilment's scan bound
  (`max(t, nm) + nf` / `min(t, 0) - nb`) is a function of `t` itself, not just `t`'s slot, so this
  shortcut is unsound there -- fulfilment is generated over the *wide*, two-period
  `_coherence_window`, imported directly from `certificate.py` (duck-typed on `.nb`/`.nm`/`.nf`,
  which `WitnessRegistry` also carries), exactly matching the re-checker's window. Get this wrong
  in a future refactor and it is the single most likely place to reintroduce a silent soundness
  bug (this is the plan's own top-listed risk).
- **`box_faithfulness_constraints(lassos)` takes its lasso list from the caller.** It does not call
  `allocate_witness_lasso` itself. The closure is static and fully known at construction (D1), so
  Phase 9's `finalize_certificate()` can either eagerly allocate one witness lasso per boxed
  closure member up front, or do so lazily as operators are evaluated -- either way, by the time
  `finalize_certificate()` actually calls `box_faithfulness_constraints`, it must pass the full,
  final lasso-index list (main plus every allocated witness lasso).
- **Phase 6, not Phase 9, is where the theory actually goes red.** The plan's
  Rollback/Contingency section names "Waves 6-8 (Phases 9-13)" as the sole unavoidably-red
  stretch and directs taking a pre-rewrite snapshot before Phase 9. That is incorrect for this
  specific class: `core.py:86` already depends on `WitnessRegistry`'s old signature, so rewriting
  the class (Phase 6, which is NOT in Wave 6-8 by the plan's own dependency table) breaks it
  immediately. Corrected inline in Phase 6's plan notes; the correction is not re-litigated here,
  just flagged so a reader of only this handoff does not miss it. No separate `git-snapshot.sh`
  invocation was needed (the working tree was clean going into Phase 6 -- the prior phase's commit
  already serves as the rollback point).
- Phase 5's round-trip work extended a dependent, already-completed adequacy-layer task's harness
  (`test_certificate_lean_agreement.py`) rather than creating the plan-named
  `test_certificate_roundtrip.py`, to avoid duplicating already-built probe/skip/subprocess
  plumbing. See that phase's plan notes for the full reasoning.
