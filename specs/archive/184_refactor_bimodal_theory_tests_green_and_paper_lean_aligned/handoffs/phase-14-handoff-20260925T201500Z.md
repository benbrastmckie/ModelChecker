## Key Decisions Made

- **`NegationOperator`/`AndOperator`/`OrOperator` were left completely unchanged.** Their
  `true_at`/`false_at` already recurse through `self.semantics.true_at`/`false_at`, which is
  exactly D5's translate-then-lookup contract once Phase 9 rewrote `semantics.true_at`/
  `false_at` themselves -- there was nothing here to fix. Their `find_truth_condition` methods
  were ALSO left in place (not deleted alongside the primitives'): they only manipulate the
  generic `{key: (true_positions, false_positions)}` shape, still structurally valid against
  Phase 11's `BimodalProposition.extension` even though nothing calls them -- deleting genuinely
  harmless, still-correct code purely for symmetry with the primitives (which WERE deleted
  because their bodies referenced now-nonexistent attributes) was judged not worth the extra
  diff. Flag if a future phase finds this inconsistency confusing enough to warrant uniform
  deletion.
- **Every operator's `print_method` converges on `general_print`, dropping `print_over_worlds`/
  `print_over_times` entirely from this theory.** These base-class helpers are shared
  framework code (other theories still use them) and were not modified; bimodal's operators
  simply stopped calling them. The design rationale: "worlds" are now certified histories shown
  in the certificate's own dedicated section (`print_certificate`), and box faithfulness's
  witness display already covers "what does the false case look like" -- there is no remaining
  need for a per-operator "show me this argument at every alternative world/time" enumeration
  duplicating that.
- **`Bot()`'s `true_at` looks up its registry bit rather than hard-coding `False` directly.**
  Local coherence already forces this bit false at every position
  (`witness_constraints.py`'s `Not(bit(lasso, t, Bot()))` clause); looking it up rather than
  hard-coding means a corrupted encoding that failed to assert that clause would surface as an
  *unconstrained* free variable (visible in a re-check failure), not a silently-correct
  Python-level `False` masking the defect.

## What NOT to Try

- Do not "fix" `NegationOperator`/`AndOperator`/`OrOperator` to also mirror `translate`'s
  dispatch table the way the primitives now do -- they are already correct via recursive
  delegation, and rewriting them to duplicate a Formula-construction rule would be a regression
  in DRY-ness, not an improvement.
- Do not call `print_over_worlds`/`print_over_times` from any bimodal operator again -- they
  read `eval_point["world"]`/`["time"]` directly, which no longer exists (D5 uses `"lasso"`/
  `"position"`), and reintroducing them would silently reintroduce the retired eval-point shape
  at exactly the print layer.
- Do not assume `sentence.operator` is an *instantiated* operator object when writing a test
  against it directly -- it is the **class** (as parsed by `Syntax`), not an instance; calling
  `sentence.operator.true_at(...)` directly invokes the unbound function with the first argument
  filling `self`. Instantiate it first: `sentence.operator(semantics).true_at(...)` (this bit
  this very phase's own test file before being caught by a `TypeError`, not silently).
