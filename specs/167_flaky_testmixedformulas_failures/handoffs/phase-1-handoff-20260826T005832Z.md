# Phase 1 Handoff: Reusable solve-cost probe harness

**Status**: COMPLETED

## What was built

- `oracle/probe_solve_cost.py` -- standalone foreground CLI (`run_probe()` + `main()`), sited
  alongside `oracle/scan_runner.py`. Replicates `Z3OracleProvider.find_countermodel()`'s settings
  dict verbatim inside `isolated_z3_context()`, builds `BimodalStructure` directly (rather than
  calling `find_countermodel()`, which raises on timeout and does not expose the structure), and
  reads the Z3 `rlimit` resource-unit statistic before any cleanup can drop the reference chain.
- `oracle/bimodal_logic/tests/test_probe_solve_cost.py` -- 10 tests, all atemporal, all
  sub-second. No `slow`/`xdist_serial`/`unstable` markers introduced.

## Scope Hypothesis outcome (deviation from plan text, not from plan intent)

The plan's access path was `structure.stored_solver.raw_solver().statistics()`. Empirically:
- `Z3SolverAdapter.raw_solver` is a **property**, not a method -- called without parens:
  `structure.stored_solver.raw_solver.statistics()`.
- `structure.stored_solver` DOES survive `_cleanup_solver_resources()` (only `.solver` and
  `.z3_model` are cleared there).
- `find_countermodel()` itself never exposes `structure`, so a probe-local replication (building
  `BimodalStructure` directly, not calling `find_countermodel()`) was necessary regardless of
  whether the statistic survives cleanup -- this was already anticipated as the fallback in the
  plan's own Scope Hypothesis text.

This is recorded as a plan-text correction, not a scope failure: the rlimit statistic is fully
reachable and confirmed working (see verification below).

## Empirical finding carried into Phase 2

`timeout_ms=0` does NOT mean "instant timeout" -- Z3 treats 0 as disabling its `timeout` option
entirely (the atemporal test formula decided normally at `timeout_ms=0` but reliably timed out at
`timeout_ms=1`). Phase 2's forced-repro step (deliberately tiny `--timeout-ms`, e.g. 2000) is
unaffected since 2000 is well above this threshold, but this is worth keeping in mind if a probe
invocation is ever given `--timeout-ms 0` expecting an instant timeout.
