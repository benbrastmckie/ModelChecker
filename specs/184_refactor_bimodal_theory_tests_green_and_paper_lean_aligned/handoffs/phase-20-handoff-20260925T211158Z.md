**DISCOVERED AND FIXED, a real pre-existing bug beyond this phase's scope**: `theory_lib/bimodal/
semantic/formula.py`'s `_TRANSLATE_CACHE` was a plain `dict` keyed by `Sentence` object identity,

create-and-discard churn of `test_oracle_provider.py`'s own `TestStateIsolation` class (100+

one of the 53-example regression test's cases when run after the isolation-stress tests in the
same process (each passed individually, only failing in combination, which is what made this
subtle). Fixed: `_TRANSLATE_CACHE` is now a `weakref.WeakKeyDictionary`, which drops an entry the
instant its key is garbage collected, strictly before that `id()` could be reused. Verified: the
full bimodal test tree (366 tests) and the full oracle test tree (463 tests, excluding the six
files reserved for Phase 21) both pass.

## Key Decisions Made

- **Fixed the `_TRANSLATE_CACHE` bug immediately rather than deferring it.** It is a genuine,
  silent correctness hazard (wrong Z3 constraints generated with no exception) that could recur
  in ANY context with enough Sentence-object churn in one process, not just this test file --
  exactly the kind of latent defect worth closing the moment it is found, per the same judgment
  call Phase 16's local-coherence fix made.
- **Kept `errors.py`'s `OracleTimeoutError` constructor signature unchanged** (still takes
  `temporal_depth`/`M`) rather than renaming `M`, to avoid rippling into
  `test_cross_oracle_differential.py` (2989 lines, explicitly NOT in Phase 20's or Phase 21's
  full-rewrite scope -- only its floor constant is Phase 21's job). `provider.py`'s own raise site
  now passes `M=back+mid+fwd` (a repurposed field, documented inline) rather than a bounded-window
  size.
- **`certificate.to_json()` is passed the search's own recorded `_premise_formulas`/
  `_conclusion_formulas`**, not empty lists, so the wire-format `target` object accurately
  describes what was actually searched (the oracle's own single-conclusion-no-premises
  convention, unchanged from the retired encoding).

## What NOT to Try

- Do not assume `--timeout`/`timeout_ms` alone can force a genuine solver timeout for testing
  purposes any more -- the certificate encoding decides everything in single-digit milliseconds.
  Use `max_rlimit=1` (Python API) or `--max-rlimit 1` (CLI) instead; both are now wired through
  and verified to force a deterministic, load-independent inconclusive result.
- Do not re-add a plain `dict` for any future Sentence-keyed or similarly identity-keyed cache in
  this theory without first checking whether a `WeakKeyDictionary` is needed -- the hazard this
  phase found is general, not specific to `_TRANSLATE_CACHE`.
- Do not touch `oracle/conftest.py`'s `_KNOWN_TIMEOUT_SKIPS` registry without also updating
  `test_timeout_skip_inventory.py` in the same edit (Phase 21's job, both files together).
