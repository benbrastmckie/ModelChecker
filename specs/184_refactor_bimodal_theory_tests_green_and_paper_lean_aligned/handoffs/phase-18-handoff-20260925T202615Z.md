- **Deviated from the plan's classification in 3 cases**, each independently confirmed by
  reading the file, not by trusting the plan's hypothesis: `test_until_since.py` moved from
  "rewrite" to "delete" (it literally asserts `z3.is_quantifier(result)`, directly contradicting
  the redesign, and every non-contradictory claim in it is already covered by
  `test_operators.py`); `test_strict_semantics.py` and `test_api_consistency.py` moved from
  "update" to "delete" (their entire premise -- `ForAllTime`/`is_valid_time`/
  `find_truth_condition` -- no longer exists anywhere in the codebase, so there was nothing left
  to update).
- **`test_data_extraction.py` and `test_injection.py` rewritten against REAL built structures**,
  not mocks (the retired versions used `Mock(spec=BimodalStructure)` with hand-set attributes).
  The certificate-based `extract_*`/`inject_z3_model_values` methods read enough interdependent
  state (`self.certificate`, `self.main_point`, `registry._bits`, etc.) that a real solve is both
  simpler to set up correctly and a strictly stronger test than reconstructing that state by hand.
- **`extract_propositions` is effectively dead code under the current framework**: it reads
  `self.syntax.propositions`, but nothing in `model_checker.syntactic`/`model_checker.builder`
  ever sets that attribute (confirmed by grep, not assumed) -- so it always returns `{}` in
  practice today. Recorded this directly as a test (`test_empty_without_syntax_propositions`)
  rather than mocking around it, plus a second test confirming the method still WORKS correctly
  if that attribute is present (in case a future caller sets it).
