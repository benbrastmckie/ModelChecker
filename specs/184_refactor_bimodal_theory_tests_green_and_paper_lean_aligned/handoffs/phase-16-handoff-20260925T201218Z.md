**DISCOVERED AND FIXED beyond Phase 16's task list**: a real soundness bug in
`witness_constraints.py`'s `local_coherence_constraints` (Phase 7's own deliverable). It asserted
the `LocalCoherentLab` biconditional only over `registry.target_window()` (one representative
position per slot), reasoning that Z3 term-sharing via `wrap()` makes one representative cover
every position sharing its slot. **That reasoning is false for the `back`/`fwd` slot adjacent to
`mid`**: e.g. with `nb=2`, slot `back[1]` occurs at `t=-1,-3,-5,...`; the neighbour an
`Untl`/`Snce` clause needs (`t+1`) lands in `mid` only at `t=-1` and in `back[0]` at every deeper
occurrence -- two genuinely different biconditionals on the same shared boolean, and only the
`t=-1` one was ever asserted. Fixed by changing `local_coherence_constraints` to iterate the wide
`_coherence_window` (matching `fulfilment_constraints`, which already did this correctly in Phase
8) instead of the narrow `target_window()`. Rewrote the module docstring's flawed "one
representative suffices" argument to record the actual counterexample.

## Key Decisions Made

- **`run_test()` bypasses `SettingsManager`.** This is a load-bearing fact for every remaining
  phase touching `examples.py`: settings dicts used by `test_bimodal.py`'s `run_test()` path must
  be COMPLETE (every key the semantics constructor reads), not partial-with-defaults-assumed. The
  `dev_cli.py`/`BuildExample` path is the only one that merges with `DEFAULT_EXAMPLE_SETTINGS`.
  Do not repeat the omission mistake in a future phase.
- **Fixed the local-coherence window bug in Phase 16 rather than deferring it.** It was discovered
  while verifying the settings migration didn't regress anything (a `dev_cli.py` smoke run over
  `example_range` surfaced the `ModelConstructionError` fail-fast on `BM_CM_1`). Since it silently
  corrupted the correctness of a large fraction of already-"complete" phases (6-15) and directly
  blocks Phase 18/19's green-suite goal, fixing it now (a small, well-isolated, well-tested change:
  one line plus a docstring correction) was judged clearly better than recording it as a debt item
  for a later phase to rediscover from scratch.
- **No expectation values were actually changed.** Every `expectation` field audited was already
  correct; the dispatch's "flip MF's expectation to True" phrasing describes what would have been
  needed if comparing against the OLD encoding's own (buggy) `z3_model_status`, not this file's
  `expectation` field, which was already `False` and correct.

  defaults apply under `pytest` -- they do not on the `run_test()` path. Always write them out
  explicitly.
- Do not assume the whole-tree pytest failure count (103 failed, 80 errored) reflects new problems
  from this phase -- it reflects the SAME pre-existing test-file-bound-to-deleted-machinery
  problem the Phase 15 handoff already flagged (there just fewer of them now, since real examples
  that were failing due to the local-coherence bug now pass). Phase 18 owns classifying and
  retiring/rewriting those files.
- Do not re-litigate the local-coherence window fix as a maybe-too-conservative change: it now
  exactly matches fulfilment's own window (`_coherence_window`, the Lean-proved
  `coherent_iff_window` bound), so it isn't a new invention, just a consistency fix.
