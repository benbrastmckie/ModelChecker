## Key Decisions Made

- Confirmed the Scope Hypothesis: `syntactic.DefinedOperator` subclasses (8 of them, including
  `\Diamond`) are always fully expanded to the 9 primitives by `Sentence.update_types` before
  `translate` is ever called (test: `TestScopeHypothesisDefinedOperatorsAreExpandedBeforeTranslate`).
  `translate` only has rules for the 9 primitives; a non-primitive operator reaching it raises
  `ValueError` naming this as the likely cause.
- Pinned the Until/Since guard/event swap with a two-sided test (`Untl(guard,event) !=
  Untl(event,guard)`), and mechanically verified swap-removal breaks the suite (temporarily
  reverted, 4 tests failed, reverted back correctly -- not committed).
- `\Future`/`\Past` (ModelChecker's G/H, "always in future/past") encoded via the Lean-derived
  double-negation identity over `Untl`/`Snce` with a trivial (`Imp(Bot,Bot)` = top) guard.
- Amendment's truth-preservation property test implemented as two independent from-scratch
  pure-Python evaluators (not a live Z3/`BimodalSemantics` extraction) -- see the plan's Phase 2
  "Deviation note" for the full rationale. Box is out of scope for this property test, matching
  the same recorded limitation the plan text attributes to `oracle/bimodal_logic/ground_truth.py`.
- `_TRANSLATE_CACHE` is a plain module-level dict keyed by sentence identity (Sentence has no
  custom `__eq__`/`__hash__`, so default identity hashing already gives "keyed by identity").

## What NOT to Try

- Do not add `\wedge`/`\vee`/`\neg`/`\Future`/`\Past` as primitive `Formula` constructors --
  D1 fixes the label alphabet as exactly the 6 Lean constructors; richer operators are rejected
  structurally by the Lean side's closure predicates.
- Do not reuse `translate`'s internal encoding logic inside `TestTranslateTruthPreservation`'s
  evaluators -- they are deliberately independent re-implementations, not calls into
  `formula.py`, so the test is a genuine cross-check rather than testing `translate` against
  itself.
