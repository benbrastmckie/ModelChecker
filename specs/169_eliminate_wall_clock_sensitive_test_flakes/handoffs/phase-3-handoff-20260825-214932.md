# Phase 3 Handoff: Deterministic Z3 `rlimit` Budgets

**Status**: [COMPLETED]

## What changed

- `code/src/model_checker/solver/z3_adapter.py`: `Z3SolverAdapter.set_rlimit(units)`, implemented
  as `self._solver.set("rlimit", units)`, added directly alongside `set_timeout()`.
- `code/src/model_checker/solver/protocols.py`: `set_rlimit()` declared on `TrackedSolverProtocol`
  only (see Scope Hypothesis deviation below) -- not on the base `SolverProtocol`.
- `code/src/model_checker/settings/types.py`: `max_rlimit: int` added to `ExampleSettings`
  (`total=False` already applies), documented as the deterministic, machine-load-independent
  complement to `max_time`.
- `code/src/model_checker/models/structure.py`: `ModelDefaults.solve()` and `re_solve()` each call
  `self.solver.set_rlimit(max_rlimit)` immediately after `set_timeout()`, only when
  `self.settings.get("max_rlimit")` is truthy -- default-off, no existing example's behavior
  changes.
- `code/src/model_checker/solver/tests/unit/test_z3_adapter.py`: 2 new tests -- `test_set_rlimit`
  (functional: a tiny rlimit exhausts on `x**4 == 123456789` and `reason_unknown()` names the
  resource limit, not a timeout) and `test_adapter_satisfies_tracked_protocol`.
- `code/src/model_checker/models/tests/unit/test_structure.py`: 5 new tests covering
  default-off/wired-on for both `solve()` and `re_solve()`, plus a UNKNOWN-is-timeout pinning test
  for the rlimit-exhausted case specifically (reason_unknown() == "max. resource limit exceeded").

## Scope Hypothesis confirmation and one deviation

`grep -rn rlimit code/ oracle/` confirmed every existing hit is a comment recording ad hoc
measurements (`theory_lib/bimodal/examples.py`, `semantic/core.py`, `operators.py`,
`oracle/bimodal_logic/tests/*.py`) -- no live rlimit call site existed anywhere, confirming this
is genuinely new capability with no parallel path to integrate with.

**Deviation** (pre-edit-gate probe result): the plan's task said to declare `set_rlimit` "matching
how `set_timeout` is declared" on `SolverProtocol`/`TrackedSolverProtocol`. Probed via
`grep -rn "def set_timeout" code/src/model_checker/solver/*.py`: `set_timeout` is **not** declared
on either Protocol class at all -- it exists only on the two concrete adapters
(`z3_adapter.py`, `cvc5_adapter.py`). Further probe: `test_protocols.py::test_z3_solver_matches_protocol`
asserts `isinstance(z3.Solver(), SolverProtocol)` against a **raw** `z3.Solver` (which has no
`set_rlimit` method) -- adding `set_rlimit` to the base `SolverProtocol` would have broken that
test. Declared `set_rlimit` on `TrackedSolverProtocol` only instead (the protocol
`create_solver()` actually returns, and the one `ModelDefaults.solve()`/`re_solve()` actually use),
confirmed safe because no test checks `isinstance(_, TrackedSolverProtocol)` against a raw
`z3.Solver` or against `cvc5_adapter`. Recorded here per the pre-edit-gate contract rather than
forcing the literal (incorrect) premise through.
