## Finding: Phase 5's inventory was incomplete

The AST scan (before any allowlisting) found 10 matching test functions, 8 already correctly
marked (the Phase 5 inventory) and 2 genuinely unmarked:
`code/tests/integration/test_timeout_resources.py::test_z3_solver_timeout` and
`::test_cli_command_timeout`. Both Phase 5 handoffs on record had claimed
"`code/tests/**` contributed none" to the wall-clock-assertion inventory; that claim does not
hold. Both are real `time.time()`-derived `assert elapsed < N` hang guards (5s and 6s budgets,
55x/~20x measured headroom per their own docstrings) sitting in the gating `-n 6` pool. Marked
both `xdist_serial` in this phase, with a comment, rather than reopening the already-closed
Phase 5 -- discovering exactly this kind of gap is this guard's stated purpose (Definition of
Done: "Zero wall-clock-asserting tests remaining in the -n 6 contended pool").

Updated inventory: `xdist_serial` now selects 9 tests (was 7); full bare collect now shows 2413
items (was 2408 -- the +5 is this phase's own unmarked `test_workflow_parity.py` tests, which
correctly stay in the gating pool since they read no wall clock); gating selection
(`not packaging and not performance and not unstable and not xdist_serial`) now selects 2291.

## Deviations from plan

1. `code/tests/ci/` was given an `__init__.py` despite the plan's literal "`__init__`-free"
   instruction: every existing `code/tests/**` and `code/src/model_checker/**/tests/**`
   subdirectory (including `code/tests/packaging/`, the plan's own named precedent) carries one,
   confirmed by inventory before writing. Followed the actual, confirmed convention.
2. `test_workflow_parity.py` parses `tests.yml` via targeted regex rather than `yaml.safe_load`,
   since `PyYAML` is not an installed dependency of either CI toolchain (confirmed via each
   toolchain's actual package list) and adding one is out of this phase's declared scope.
3. `code/tests/integration/test_timeout_resources.py` was marked (2 functions) -- outside this
   phase's literally-named "Files to modify" list -- because the new AST guard's own operation
   surfaced a genuine, previously-undetected gap in Phase 5's already-closed inventory (see
   Finding above). Not marking them would have made the freshly-written guard fail immediately.
