## Bugfix found during Nix-toolchain verification

The first `nix flake check -L` run of this phase failed (`EXIT:1`, 5 errors) in
`code/tests/ci/test_workflow_parity.py`: `FileNotFoundError` reading
`/build/.github/workflows/tests.yml`. Root cause: `flake.nix`'s `checks.default` derivation sets
`src = ./code`, so the sandboxed build's tree is exactly `code/`'s own contents -- `.github/` and
`flake.nix` itself, both living outside `code/`, are structurally absent there. This module's
`REPO_ROOT = Path(__file__).resolve().parents[3]` correctly resolves to the repo root in a normal
checkout, but resolves to `/build` (one level above the copied `code/`) inside the Nix sandbox,
where no `.github/` or `flake.nix` exists.

Fix: added a `pytest.skip(..., allow_module_level=True)` guard at module import time when either
`TESTS_YML` or `FLAKE_NIX` does not exist on disk, with a comment explaining the sandbox's
`src = ./code` scoping and noting the guard still does its real job in
`.github/workflows/tests.yml`'s `general-tests` job, where `actions/checkout@v4` provides the
full repository. Verified the skip fires cleanly (not an error) by copying `code/` alone into a
directory with no repo-root siblings and re-running the module there (`1 skipped`, exit 0), then
re-ran the full `nix flake check -L`, which passed clean on the second attempt.

This fix touches a file Phase 7 created/committed, but is recorded here since it was discovered
and applied during this phase's own toolchain verification step, not deferred.
