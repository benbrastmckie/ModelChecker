# Phase 2 Handoff: E-Matching Trigger Patterns (Rejected Candidate)

- **Task**: 144 - fix_oracle_per_formula_solve_timeouts
- **Phase**: 2 of 5
- **Status**: COMPLETED (candidate tested and rejected; encoding reverted to comment-only dead-end
  records, no behavioral change survives)

## What Was Tried

Explicit `patterns=` E-matching triggers were added to all four unpatterned quantifier sites the
research report identified as pattern-eligible function applications:

1. `NecessityOperator.true_at` (`operators.py`): `patterns=[is_world(other_world)]`
2. `depth_bounded_skolem_abundance_constraint` (`core.py`): `patterns=[shift_of_bounded(source_world, shift_amount)]`
3. `capped_skolem_abundance_constraint` (`core.py`): `patterns=[shift_of_capped(source_world, shift_amount)]`
4. `matching_states_when_shifted_var` (`core.py`): `patterns=[z3.Select(source_array, time)]`

All four were confirmed **legal** by Z3 (no error, no silent discard -- each pattern covers every
bound variable of its quantifier).

## Why All Four Were Reverted

Bisection against `test_soundness_regression.py` (which must stay green per the plan's semantics-
preservation gate) found that **either** the `depth_bounded_skolem_abundance_constraint` pattern
**or** the `matching_states_when_shifted_var` pattern, applied alone, regresses `\Future p` (F(p))
from a ~3s solve to a 5000ms `OracleTimeoutError`
(`TestBoundaryVacuity::test_depth1_boundary_safe_is_true` and
`::test_depth1_countermodel_has_required_fields`). Both reverted patterns sit on the frame
constraint (`depth_bounded_skolem_abundance_constraint`) that is shared by **every** depth-1, M=3
formula, not only the plan's three named targets -- F(p) is not one of the three targets but shares
this constraint. This is exactly the risk the plan's own risk table flagged ("a trigger pattern is
too restrictive and suppresses a needed instantiation"), manifesting as a cost/timeout regression on
a formula outside the measured benchmark set rather than a soundness flip (`disagreements` would
still read 0; the formula simply times out instead of deciding).

With those two abundance-constraint patterns reverted, the remaining `NecessityOperator` +
`capped_skolem_abundance_constraint` patterns pass the full 30-test `test_soundness_regression.py`
suite green. `capped_skolem_abundance_constraint` is never reached by any of the three target
formulas (all have M=3, which always dispatches to `depth_bounded_...`, not `capped_...`), so it
had zero measurable effect either way. `NecessityOperator`'s pattern is exercised only by
`and_box_next` (the only target containing `\Box`), and a paired 7-run measurement round against
the Phase 1 baseline showed:

| Metric | Baseline | Phase 2 (necessity+capped only) | Verdict |
|---|---|---|---|
| median(rlimit) | 130,120,807 | 130,120,813 | ~0.00% (neutral) |
| max(rlimit) | 213,334,140 | 192,875,085 | improved |
| median(wall) | 46.54s | 42.13s | ~9.5% faster |
| seeds w/ negative rlimit delta | -- | 2 of 5 (seeds 1, 3) | fails >=4-of-5 rule (D) |

Per the plan's binding acceptance rules, this is a **neutral** result (median rlimit change < 10%)
combined with a failed consistency rule (D), so it is rejected and reverted, not kept -- "a
neutral-but-complicating change to a correctness-critical encoding is a net negative."

## New Dead Ends (continuing the research report's numbering from 6)

7. **`patterns=[z3.Select(source_array, time)]` on `matching_states_when_shifted_var`'s inner
   `ForAll([time], ...)`** (Task 144): legal, Z3-accepted trigger. Regressed `\Future p` (F(p)) from
   ~3s to a 5000ms timeout by starving this shared axiom's instantiation for formulas whose ground
   term set does not yet contain the needed `Select(source_array, time)` application. This
   constraint is nested inside every abundance-axiom instantiation, so a narrow trigger here
   regresses the whole depth-1 temporal-operator family even when it happens to help one target
   formula. Reverted.
8. **`patterns=[shift_of_bounded(source_world, shift_amount)]` on
   `depth_bounded_skolem_abundance_constraint`** (Task 144): legal, Z3-accepted trigger, and the
   plan's highest-leverage candidate (active for all three Phase 1 targets). Independently
   reproduces the same F(p) regression as dead end 7 (either pattern alone is sufficient to trigger
   it). Reverted.
9. **`patterns=[is_world(other_world)]` on `NecessityOperator.true_at`** (Task 144): legal,
   Z3-accepted, does not break any test, but measured **neutral**: median rlimit unchanged
   (130120813 vs 130120807, ~0.00%) and the per-seed sign was inconsistent (negative on only 2 of 5
   seeds). Rejected under the plan's neutral-candidates-are-reverted policy, not because it is
   harmful but because it has no measured benefit.
