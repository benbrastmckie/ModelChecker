## Design decision carried into Phase 2

`sample_once()`'s existing return shape (`dict[int, int]` of pid -> rss) is preserved unchanged
— several existing tests assert against that exact shape and must not be modified. Worker-id
attribution instead threads through `PeakTracker.record(sample, worker_ids=None)`, an
**additive** optional second parameter (backward compatible with every existing call site that
omits it). `PeakTracker` gains `pid_to_worker: dict[int, str | None]`; `summary()` gains
`pid_to_worker` and `per_worker_id_peak_kb`. `run()` will separately discover worker ids per
sampled pid using the new `read_xdist_worker_id()` and pass that map into `record()`.
