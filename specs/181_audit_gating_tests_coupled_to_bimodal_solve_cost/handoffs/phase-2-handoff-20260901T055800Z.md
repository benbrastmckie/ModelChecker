# Phase 2 Handoff: `create_test_model()` honors `theory_name`, defaults to logos

**Status**: COMPLETED

## What changed

- `code/tests/utils/helpers.py::create_test_model()`: resolves `theory_name` via
  `model_checker.api.get_theory()` instead of hardcoding `theory_lib.bimodal`; default changed
  from `'bimodal'` to `'logos'`.
- `code/tests/utils/base.py::BaseModelTest.create_model()`: gained an optional `theory_name`
  parameter (default `'logos'`), forwarded to `create_test_model()`.
- Five call sites across `test_performance.py`, `test_error_handling.py`,
  `test_timeout_resources.py` pinned to `theory_name='bimodal'` explicitly (see plan's Phase 2
  deviation record for the full list and reasons) — logos's own `DEFAULT_EXAMPLE_SETTINGS` is
  expensive (N=16 + four constraint flags all True), so settings calibrated against bimodal's
  cheap defaults do not transfer safely.

## Critical finding for downstream phases

logos's `DEFAULT_EXAMPLE_SETTINGS` (`N=16, contingent=True, non_empty=True, non_null=True,
disjoint=True`) is NOT cheap the way bimodal's is (`N=2, contingent=False`, etc.). Any future
logos swap (Phase 3, Phase 4) must check whether the swapped fixture relies on an implicit/large N
or omits explicit constraint-flag overrides — the same class of danger this phase hit five times,
including one uncontrolled 13.6GB RSS incident that required a manual process kill. Always verify
a logos swap with live memory monitoring before trusting a green run, not just exit code 0.
